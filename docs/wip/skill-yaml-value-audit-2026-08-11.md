# Skill YAML の値/参照 監査 — 着手時ハンドオフ

**目的**: skills/ 配下の各 skill (task-routing / task-slicing / wave-status /
finish-task / intent-clarify / commit-message) の YAML 契約 (= Final Report
スキーマ、および wave-status の state ファイル形式) を、原則
「**受け渡し YAML / state は値 (データ) を持たず、ありか = 成果物ファイルへの
パス参照と、判断・ステータスだけを持つ**」で再精査する。

**背景** (2026-08-11、ow-review のチェーン設計議論で確定):
値を YAML に複製すると (a) 正典ファイルとの二重管理で「どちらが正か」問題が
起きる、(b) YAML 1.1 の暗黙型変換 (例: 引用符なし `7:47` は 60 進数の 467 に
パースされる) でデータが静かに壊れる。ありか参照だけなら両方が構造的に消え、
スクリプトでのパース需要も生まれない (PyYAML 等の依存が永久に不要)。

## やること

1. 各 skill の Final Report スキーマと state ファイル形式を洗い、フィールドを
   「値の埋め込み (特に時刻・数値・成果物の中身の転記)」と
   「パス参照・判断・ステータス」に分類する
2. 値埋め込みのうち、正典ファイルが既にある / 作るべきものを特定し、
   参照化の修正案を出す
3. **過剰適用しない**: 判断の要約 (verdict / Y-trace / 理由 1 行 / status enum)
   は値ではなく判断なので対象外。evidence の「5〜10 行抜粋」(finish-task) は
   「フルログはファイルへ、抜粋をレポートに」という設計意図があるので、
   抜粋 + `ref` パスの併記が保たれているかだけ確認する
4. 修正は user 承認後。skillshare sync --all で各 vendor へ配布される点に注意
   (配布先での互換性、既存 state ファイルの移行要否も確認)
